# MIS-427 — Registration and checkout layout repair (2026-09-27)

- **Job/problem:** A student choosing a course, entering identity, and reviewing payment should see one predictable registration flow. The current mobile order card dominates the form, while Portal sign-in, placement, payer, and pickup notes read as disconnected insertions.
- **Interaction model:** Keep the existing three-step Route → Details → Review flow. On desktop use a primary form/review column with a narrow sticky order summary. On mobile lead with a compact price/fulfillment summary that can expand to show itemized CRM-quoted lines; the form remains the visual priority.
- **Visual direction/reference mode:** Inspiration mode grounded in the shipped AIT Placement/Portal palette: navy outer canvas, one ivory workspace, restrained gold accents, warm borders, short utility footer. No new visual reference overrides the accepted shell.
- **Locked behavior:** Course/modality and residence eligibility, optional tuition, CRM quote authority, optional Portal sign-in and saved draft, guest checkout, placement linkage, separate payer, shipping fields, secure hosted payment, and review totals remain unchanged.
- **Non-goals:** CRM frontend, pricing logic, payment capture, registration data writes, global header or public site redesign, production promotion.
- **Layout invariants:** One header/progress rhythm across steps; fields grouped by student, payer, and shipping jobs; no duplicate fulfillment note in the form; order summary subordinate to the form at 390px; primary action visually strongest and reachable without horizontal overflow. Content must tolerate long course labels, two quote lines, expanded shipping, and errors.
- **Primary CSS viewports:** 1440×900 and 390×844. Regression: 360×800 and 1024×768. Verify route, details, review, optional tuition, and non-English route with live CRM quotes. Inspect screenshots, scroll, focus, network and browser errors. Do not click hosted checkout or create records during read-only QA.
