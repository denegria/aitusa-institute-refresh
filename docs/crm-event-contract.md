# CRM event contract

Linear issue: MIS-277

This contract defines the safe boundary between the AIT USA public site/student
portal and AIT CRM. The site may create validated event envelopes locally, but
this slice does not write to AIT CRM, store events durably, or configure a retry
queue.

## Event taxonomy

The initial taxonomy covers:

- `lead_form_submitted`
- `placement_started`
- `placement_completed`
- `whatsapp_cta_clicked`
- `portal_sign_in`
- `lesson_viewed`
- `lesson_completed`
- `ai_practice_started`
- `ai_practice_completed`
- `attendance_scan`
- `payment_started`
- `payment_completed`
- `payment_failed`
- `profile_updated`

## Required envelope fields

- `type`: one of the approved event types.
- `idempotencyKey`: stable key generated by the caller for retry safety.
- `occurredAt`: ISO timestamp from the event source.
- `actor`: CRM contact reference, portal account id, or anonymous id.
- `source`: surface and path where the action occurred.
- `consent`: basis and optional policy version.
- `payload`: safe summary metadata only.

## Privacy boundaries

The validator rejects sensitive payload fields such as raw audio, transcripts,
recording URLs, card numbers, provider subjects, passwords, tokens, and SSNs.
Raw audio/transcript storage remains blocked until MIS-279 approves privacy,
consent, and retention policy.

## CRM behavior

Current route: `/api/portal/events`

The route returns accepted/rejected local contract responses and includes a
safe CRM timeline preview. It never writes to AIT CRM in this slice. A future
slice can attach this contract to a CRM adapter, durable outbox, idempotency
store, and retry worker after the API contract is approved.
